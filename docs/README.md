# YouTube Description Generator — Documentation

A four-step pipeline that turns `.mp4` files into upload-ready Shorts text, using two models that
both run locally.

```
src/youtube_description_generator/
├── cli.py                     the ytdg command
├── extract_frames.py          .mp4 → one JPEG per second
├── describe_frames.py         frames → BLIP captions → description.txt
├── summarize_descriptions.py  captions → Ollama → title, description, hashtags
└── collect_files.py           description.txt → {folder}.txt
```

## Everything runs locally

BLIP through Transformers, and an LLM through Ollama. There is no API key, no account, and no
upload — which matters here specifically, because the input is unpublished video.

The cost is the downloads: PyTorch, the BLIP weights (~1 GB), and an 8B Ollama model. All are
one-time.

## Before you re-run a stage

The pipeline passes state through one filename, and `summarize` **overwrites** it.

| Step | Reads | Writes |
|---|---|---|
| `extract` | `{video}.mp4` | `{video}_frames/frame_NNNN.jpg` |
| `describe` | the frames | `{video}_frames/description.txt` — **skipped if it exists** |
| `summarize` | `description.txt` | `description.txt`, replaced |
| `collect` | `description.txt` | `{folder}.txt` in the base directory |

So running `summarize` twice summarises its own output, and the captions it consumed cannot be
regenerated by `describe` because the file still exists. See
[`internal/known-issues.md`](./internal/known-issues.md).

## A note on the output filename

`collect` names the result after the **folder**, which is `{video}_frames` — so you get
`myvideo_frames.txt`, not `myvideo.txt`. That is what the code and its tests do, and what
`move_files.bat` did before them. Earlier documentation said otherwise.
